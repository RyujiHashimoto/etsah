# PROUT 情報フロー制御 — プレゼンテーション構成

PII 漏洩をコンパイル時に止める仕組みを、12 枚で説明する構成です。対象はソフトウェアエンジニアとセキュリティ担当者で、前提知識として関数型の型注釈と sink という言葉を知っている読者を想定しています。

## 全体の流れ

前半 4 枚で「なぜ必要か」を示し、中盤 5 枚で「どう動くか」を具体例と検査の順に説明し、後半 3 枚で「再利用・限界・次の一歩」を扱います。各ページのメッセージは一つに絞り、コードと図で根拠を示す構成です。

| # | スライド | 伝えること |
|---|---|---|
| 1 | PROUT 情報フロー制御 | 表紙。PII 漏洩をコンパイル時に止める、という一行の約束。 |
| 2 | AI の開発速度に、漏洩チェックが追いつかない | 生成量、ログ・分析基盤・第三者 API への流出、プロンプトインジェクション、事後検知の限界。 |
| 3 | 既存の対策は、なぜ足りないのか | コードレビュー、DLP・マスキング、実行時 taint の 3 つを比較し、どれもコンパイル時の保証ではないと結論する。 |
| 4 | 発想：ラベルを型の一部にする | `String @pii` のように型へラベルを書く。public は暗黙、record は全フィールドの和集合、フィールド参照は個別。 |
| 5 | 全体像：4 つの部品と 3 つの関門 | ラベル、型、sink ポリシー、declassify の 4 部品。引数・戻り値、sink、native sends の 3 関門。 |
| 6 | 具体例：領収書は送れるが、分析イベントには送れない | `customer.email` は `send_receipt` を通り `net(email)` で許可される。`track_event` に渡すと `E-IFLOW-ARG`。 |
| 7 | 関門 2：引数を変えても、sink ポリシーが止める | `track_event(event: String @pii)` に変えても、`net(analytics)` が拒否して `E-IFLOW-SINK`。2 つの関門は独立している。 |
| 8 | native 実装は、sends で行き先を宣言する | `sends to -> net(email)` が実装の行き先を表す。宣言のない native op は `E-SINK-UNBOUND`。 |
| 9 | declassify：例外を、監査可能にする | ポリシー・スコープ・ロール・理由を要求し、許可時は `W-DECLASS` を残す。値の変換ではなく、ラベルを下げる宣言。 |
| 10 | パターン層：再利用しても、ポリシーは緩まない | `data_policy` のマージ。許可は交差、拒否は和集合、declassify は交差。満たせなければ `E-POLICY` で fail closed。 |
| 11 | 限界と次の一歩 | ラベル漏れ、native の信頼、暗黙フロー、実行時の強制。v0.1 静的検査、v0.2 分岐とパターン層、v0.3 実行時 `Labeled<T>`。 |
| 12 | AI が書いたコードを、信頼できる基盤に。 | 3 つの関門のまとめと、リポジトリへの導線。 |

## 各ページの構成要素

2 枚目は写真を左に置き、右側に 4 つの短い指摘と「漏洩は、実行時ではなく設計時に止める」という結論を置きます。3 枚目は 3 枚の概念図を横に並べ、最後に「どれもコンパイル時の保証ではない」と一文で閉じます。

4 枚目は型定義のコードを右側に置き、`type Customer { email: String @pii }` が最小の例になるようにします。5 枚目は中央にコンパイラコアの図を置き、左右に 4 つの部品と 3 つの関門を配置します。

6 枚目と 7 枚目は、同じ `track_event` を引数の検査と sink の検査で二度止めます。ここが本資料の中心です。8 枚目は native の `sends` 宣言を、9 枚目は `declassify` の監査性を扱います。

10 枚目はパターンの `data_policy` とアプリの `policy` のマージ規則を、許可・拒否・declassify の 3 行に整理します。11 枚目は 4 つの限界を並べ、最後にバージョンの進化を一本の帯で示します。

## デザイン方針

背景はミネラルホワイト `#F4F7F6`、見出しは深いスレートブルー `#304C59`、本文は `#1C2326`、補足は `#5B6B73` です。PII とエラーは錆色 `#C35233`、許可された経路は深い緑 `#3A7D64` で示します。見出しは Noto Serif JP、本文は IBM Plex Sans JP、コードは JetBrains Mono で組み、左下に `[✓] PROUT`、右下にページ番号を置きます。

南京錠・盾・ハッカーといったサイバーセキュリティの記号は使わず、データフロー、型、検査の構造そのものを図で見せます。コードは装飾ではなく、検査がどこで働くかを示す証拠として扱います。
